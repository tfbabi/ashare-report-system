# 交付规范

所有报告类交付遵循同一套规范，由统一的 Markdown → HTML 转换器
（见 [tools/md_to_html_email.py](../tools/md_to_html_email.py)）落地，
改一处、全任务生效。

## 形式

- 邮件：**正文简要 + 完整报告 HTML 附件**；聊天里只留短摘要
- 结论先行：开头 2–3 行给定性、最重要判断、接下来盯什么
- 说人话：术语跟大白话解释，短句，长段必拆；
  每只票先给「买什么 / 现价 / 证伪线」，再给理由
- 重点标红全文 ≤5 处（核心结论、证伪线、利空、最重要标的）

## 名单表格标准

选股名单统一表格展示，名称与代码分列。标准列集：

题材｜概念｜名称｜代码｜现价（涨幅在前）｜开盘涨幅｜当前较昨日放量｜
黄均线｜图形形态（5 日线位置+距离）｜连涨天数｜市值｜证伪线｜一句理由

- 表格内所有带符号百分比一律红涨绿跌着色加粗（不限于涨幅列）
- 证伪线列自动橙红加粗；整行状态高亮（涨停红、走强蓝）
- 由 `tools/table_fields.py` 一次算齐标准字段，保证各任务口径一致

## 股票链接规范（全邮件通用）

- **名称挂本地看盘跳转**（点名称在本地看盘软件打开该股）
- **代码挂东方财富网页链接**；网页链接只许加在代码上
- 只有名称的提及：只给名称挂本地跳转，不配网页链接
- 简要名单必须名称、代码成对出现，链接才有处可挂

## 质量红线

- 剔除 ST 股；总市值 >1000 亿的个股不进正式与观察名单，
  只许在方向锚里提一句（研究线例外：柚子线按其自身模型，
  不设市值上限；外部公式模型按公式本身）
- 正式名单必须可买：已封板票单列名单最后，只作强度确认
- 盘中正式名单不收当日已大幅冲高且无回踩承接结构的票
- 名单目标 4–6 只、正式 + 观察合计 ≥8 只、新面孔 ≥1/3，
  按热点逐条交代、每个方向给 2–3 只不同位置
- 数量不设上限：符合各线模型标准的票全展示；
  不得以成交额小为由排除或降档合格票（容量票只作方向锚定）
- 新股上市必须同时给出：主业、题材（按市场实际炒作归属）、
  合理估值区间与现价偏离
- 近期利空（减持/定增/大额解禁/业绩预亏/立案/退市风险）单独醒目提醒
